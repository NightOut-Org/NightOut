# Party Set — กฎธุรกิจ (เคาะ 2026-10-06 · อัปเดตตาม requirement 2026-10-11)

> **อัปเดต 2026-10-11** ตาม [`docs/REQUIREMENTS.md`](REQUIREMENTS.md): ยกเลิกกลุ่มคืนเต็มเมื่อ ≥24 ชม. หลังจากนั้นริบ (ไม่มีคืนครึ่ง) · เช็กอินสำเร็จเมื่อสมาชิกคนแรกสแกน (ไม่ใช้เกณฑ์ ≥50%) · มัดจำประมาณ 200–300 บาท/คน · ไม่มีพรีออเดอร์เซ็ต — ข้อ 3 ด้านล่างปรับแล้ว (ยังไม่ทำในโค้ด)

> สถานะ: **ตัดสินนิยามและนโยบายหลักแล้ว** · ตัวเลขที่ทำเครื่องหมาย ⚠ ยังรอเจ้าของเคาะ · ยังไม่ได้เขียนโค้ด/migration

## 1. ตัดสินแล้ว

| เรื่อง | ข้อสรุป |
|---|---|
| Party Set คืออะไร | **การจองโต๊ะกลุ่ม + ราคาเซ็ตอ้างอิง** — จองเฉพาะโต๊ะ/โซนสำหรับกลุ่มใหญ่ (ร้านกำหนดช่วงคน เช่น 6–8) ราคาเซ็ตแสดงเพื่อประเมินงบ **ไม่ขาย ไม่รับสั่ง ไม่ชำระค่าเครื่องดื่มผ่านเว็บ** (ตรงกับกฎ "ไม่มีสั่งอาหาร/เครื่องดื่ม/แพ็กเกจล่วงหน้า") |
| เงินที่จ่ายผ่านเว็บ | **มัดจำอย่างเดียว** ผ่าน Beam Payment แบบ Escrow (ไม่มีโอน + แนบสลิป · อัปเดต 2026-10-11) → ถือไว้ → เช็กอิน/ไม่มา |
| มัดจำคิดอย่างไร | **ต่อหัว (`deposit_unit = PER_PERSON`) มีเพดานต่อการจอง** — ร้านตั้งบาท/คนเอง |
| ยกเลิก / ลดจำนวนคน | **เข้มกว่าโต๊ะปกติ** (ตารางข้อ 3) |
| ส่วนที่เหลือ | จ่ายที่ร้านตามบิลจริง · มัดจำที่เช็กอินแล้วถือเป็นเครดิตหักบิลตาม flow เดิม |

## 2. ค่าเริ่มต้นที่เสนอ (⚠ รอเคาะตัวเลข)

- ⚠ มัดจำต่อหัว: ร้านตั้งเอง (เสนอช่วง 100–500 บาท/คน)
- ⚠ เพดานมัดจำต่อการจอง: ค่ากลางของระบบ (เสนอ 5,000 บาท) เก็บใน `platform_settings`
- ⚠ จำนวนเซ็ตสูงสุดต่อร้าน: 3
- ⚠ ค่าคอม: ใช้ `billing_events` เดิม (CHECK_IN / NO_SHOW) — ยังต้องเคาะว่าคิดเป็น % ของมัดจำหรือเป็นต่อหัว

## 3. นโยบายยกเลิก / ลดจำนวนคน (เข้มกว่าโต๊ะปกติ)

| กรณี | ผล |
|---|---|
| ยกเลิกก่อนถึงเวลาจอง **≥ 24 ชม.** | คืนมัดจำเต็ม |
| ยกเลิก **< 24 ชม.** หรือไม่มา | ริบมัดจำ (โอนให้ร้านหรือเก็บเป็นเครดิตตามที่ระบบทำอยู่) |
| ลดจำนวนคน ≥ 24 ชม. ก่อนเวลา และยังไม่ต่ำกว่า `pax_min` | ⚠ ยังไม่ระบุในเอกสาร (เดิมเสนอ: ปรับมัดจำตามหัว คืนส่วนต่างเต็ม) |
| ลดจำนวนคนต่ำกว่า `pax_min` | นับเป็นยกเลิกทั้งการจอง ตามเวลาในตารางด้านบน |
| ลดจำนวนคน < 24 ชม. | ไม่คืนส่วนต่าง |
| สมาชิกคนแรกสแกน QR ภายในเวลา | นับว่าเช็กอินสำเร็จ — ไม่ริบมัดจำ |
| ไม่มีใครมาภายในเวลา (สายเกิน 30 นาที) | Forfeited ร้านยึดมัดจำ 100% |

## 4. กติกาอื่น

- ใช้โปรโมชันของร้านได้ **1 อย่าง** ตามกฎเดิม ไม่ซ้อนส่วนลด
- ร้านสร้าง/แก้เซ็ตเอง **แอดมินตรวจถ้อยคำก่อนแสดง** (เหมือน `bar_promotions`)
- ถ้อยคำ: ใช้ "โต๊ะกลุ่ม / ราคาเซ็ตอ้างอิง" ห้ามใช้คำชวนซื้อเหล้า ("สั่งเลย", "ซื้อเซ็ต", "ราคาพิเศษเหล้า")
- **กฎหมาย:** ถ้าเปลี่ยนเป็นการขายเครื่องดื่มแอลกอฮอล์ล่วงหน้าบนเว็บ จะเข้าข่ายข้อห้ามขายผ่านช่องทางอิเล็กทรอนิกส์ — ต้องผ่านที่ปรึกษากฎหมายก่อน และต้องแก้กฎใน `CLAUDE.md`

## 5. ผลกระทบต่อระบบ (ยังไม่ได้ทำ)

ของที่มีอยู่แล้วและใช้ต่อได้: `bar_booking_settings.deposit_unit/deposit_amount`, `grace_minutes`, `price_packages` (pax_min/pax_max/total_price), `booking_deposit_consents`

ของที่ต้องเพิ่ม:

1. **DB** — `price_packages.is_party_set boolean`; ตารางหรือฟิลด์นโยบายยกเลิกแบบขั้นบันได (ปัจจุบันมี `refund_before_hours` ค่าเดียว) + ฟิลด์อัตราคืนบางส่วน; `platform_settings` เพดานมัดจำ; สถานะ/การบันทึกคืนบางส่วน (ตอนนี้มีแค่ REFUNDED / FORFEITED เต็มจำนวน)
2. **Logic** — ฟังก์ชันคำนวณมัดจำ (ต่อหัว + เพดาน) และอัตราคืนตามเวลา ใน `@nightout/utils` พร้อมเทสต์ · กติกา "มา ≥ 50%" ในขั้นตอนเช็กอิน
3. **Consent** — เนื้อหา `depositTermsText()` ต้องรวมตารางข้อ 3 → **ขึ้น `DEPOSIT_TERMS_VERSION`**
4. **UI** — หน้าร้านแสดงเซ็ตกลุ่ม · Checkout แสดงมัดจำ+เพดาน+เงื่อนไขยกเลิกแบบขั้นบันได · `/merchant/settings` ตั้งเซ็ตและมัดจำต่อหัว · แอดมินตรวจถ้อยคำ
5. **เอกสาร** — `DATABASE.md` (ข้อ 5.0), `SITEMAP.md`, ADR ถ้าเปลี่ยนโครงสร้างตารางยกเลิก
