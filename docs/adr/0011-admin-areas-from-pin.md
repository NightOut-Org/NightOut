# ADR 0011: พื้นที่ร้าน (จังหวัด → อำเภอ/เขต → ตำบล/แขวง + ย่าน) เก็บใน DB และหาจากหมุดร้าน

- **สถานะ:** Accepted
- **วันที่:** 2026-10-20

## Context
ย่านเดิมมีแค่ 10 ย่านใน `seed.sql` ร้านต้องเลือกเองตอนสมัคร/แก้ข้อมูล ร้านนอก 10 ย่านนั้นเลือกไม่ได้ และหน้าค้นหา Hero onboarding ความชอบ อันดับรายย่าน ใช้รายการเดียวกันนี้หมด เจ้าของต้องการให้รองรับทั้งประเทศโดยไม่ต้องมีคนเพิ่มย่านเอง (นอก MVP — อนุมัติ 2026-10-20)

ทางที่พิจารณา
1. **เรียก API ตอนปักหมุด** (Nominatim ที่ใช้อยู่ใน ADR 0009 / Longdo / Google) แล้วเก็บชื่อไว้กับร้าน — งานน้อย แต่ชื่อไม่สม่ำเสมอ (เขตวัฒนา / วัฒนา / บางหมุดไม่มีตำบล) ไม่มีรหัสให้จัดกลุ่ม และพึ่งบริการภายนอกตอนบันทึก (Google ใช้ไม่ได้ตามกฎแผนที่)
2. **นำเข้าเขตการปกครองพร้อมขอบเขตไว้ใน DB** แล้วหาจากหมุดด้วย PostGIS — ไม่พึ่งบริการภายนอก ได้รหัสทางการ ชื่อสม่ำเสมอ แต่ต้องมี migration ข้อมูลขนาดหลาย MB

ชื่อ "ย่าน" ที่คนเที่ยวใช้ (ทองหล่อ เอกมัย) ไม่มีแหล่งทางการ ทั้งสองทางได้มาจาก OpenStreetMap เหมือนกัน

## Decision
ใช้ทางที่ 2 (เจ้าของเลือก 2026-10-20)

- **เขตการปกครอง:** OCHA COD-AB Thailand (Royal Thai Survey Department, OCHA ROAP · CC BY-IGO) — ตาราง `provinces` / `amphoes` / `tambons` ใช้รหัส pcode (`TH10` / `TH1039` / `TH103902`) · ขอบเขตตำบลลดความละเอียด 0.0002° (≈ 22 ม.) เก็บเป็น TWKB precision 4 ใน migration `…20261020000400` (~6 MB)
- **ย่าน:** `districts` เดิม + จุดกลาง/รัศมี/priority — ทีมคัดเอง (SEED) ชนะ OSM · OpenStreetMap `place=suburb|quarter|neighbourhood` ชื่อไทย (ODbL) ตัดชุมชน/หมู่บ้าน/ชื่อที่ซ้ำกับอำเภอ-ตำบล · หมุดอยู่ในหลายย่าน = ย่านที่แคบสุดชนะ (อโศก ชนะ สุขุมวิท)
- **ร้านไม่เลือกพื้นที่เอง:** trigger `bars_set_area` ตั้ง `tambon_code` + `district_id` ทุกครั้งที่หมุดเปลี่ยน (สมัคร · แอดมินอนุมัติ/แก้หมุด) · `district_id` ถูกตัดออกจาก body ของฟอร์มร้านและ Backoffice
- **หน้าเว็บ:** `GET /public/catalog` ส่ง `areas` (view `bar_areas`) + รายชื่อ `districts` / `amphoes` / `provinces` ทั้งประเทศ · ตัวกรองพื้นที่ใช้ชื่อ (`?district=` เดิม ตรงกับย่าน/อำเภอ/จังหวัด) ค้นได้ทุกพื้นที่ พื้นที่ที่มีร้านขึ้นก่อน (Hero/ปุ่มลัดแสดงเฉพาะตัวเลือกเด่น) · ตอนปักหมุดเรียก `GET /public/area` (`area_at_point`) แสดงผลให้ร้านเห็น
- **ตำบล/แขวง** (7,425 · ใหญ่เกินส่งใน catalog): ค้นจาก backend ตอนพิมพ์ ≥ 2 ตัวอักษร (`GET /public/tambons` · rpc `search_tambons` · backend ของเราเอง ไม่ใช่ Nominatim จึงไม่ติดนโยบายห้าม autocomplete) แล้วกรองด้วยรหัส (`?tambon=`) เพราะชื่อซ้ำกันข้ามจังหวัด · ชื่อถนน/ซอยไม่มีในชุดข้อมูลใด → ช่องค้นหาหลักค้นจากที่อยู่ร้าน
- **ที่มาของข้อมูล:** ระบุ OCHA (CC BY-IGO) และ © OpenStreetMap ทุกที่ที่แสดงพื้นที่จากหมุด (`ui/components/pinAreaCard.tsx`) · สร้างข้อมูลใหม่ด้วย `apps/backend/scripts/areas`

## Consequences
- **ได้:** ครบทั้งประเทศตั้งแต่วันแรก ไม่ต้องมีหน้าเพิ่มย่าน · ร้านเลือกผิดไม่ได้ · หาพื้นที่ ~0.4 ms ใน DB ไม่มีบริการภายนอก
- **เสีย:** repo มี migration ข้อมูล ~6 MB · ชื่อย่านขึ้นกับคุณภาพ OSM (ย่านดังที่ OSM ไม่มีต้องเพิ่มใน `seeds.json` แล้วสร้าง migration ใหม่) · ขอบเขตที่ลดความละเอียดอาจทำให้หมุดชิดเส้นแบ่งตำบลได้ตำบลข้างเคียง
- เพิ่ม/แก้ย่านหรืออัปเดตเขตการปกครอง = migration ใหม่ (ห้ามแก้ไฟล์ที่ push แล้ว)

## ภาคผนวก 2026-10-21 — ย่านเพิ่ม + ย่านหลายจุด + พื้นที่ที่ชอบ
- ย่านที่ยาวเป็นแนว (พหลโยธิน) เก็บเป็น `districts.area` (พื้นที่รวมวงกลมหลายจุด) แทนวงกลมเดียว · `district_near` เลือกย่านด้วย priority → รัศมีแคบสุด → ใกล้จุดกลางสุด เหมือนเดิม
- จุดอ้างอิงของย่านใหม่ใช้จุดกลางตำบลทางการเฉพาะตำบลที่ไม่กระจาย ไม่เช่นนั้นใช้พิกัด OpenStreetMap ที่ยืนยันแล้ว (ห้าง สถานี ชุมชน) — จุดกลางตำบลชนบทคลาดได้เป็นสิบกิโลเมตร
- ผู้ใช้เลือก "พื้นที่ที่ชอบ" ได้ทุกระดับ: ย่านเก็บ `preferred_district_ids` · จังหวัด/อำเภอ/ตำบลเก็บรหัส pcode ใน `preferred_area_codes`
- ยังไม่ทำ: กรองตามชื่อถนนจากข้อมูลถนน OSM (ต้องดาวน์โหลดเพิ่ม รอผู้ใช้อนุญาต)
